# 迁移到 Lumina Sheets 1.x

当前项目仍处于 0.29 开发线。本文先固定接入方式，1.x 发布时会在同一文件补充从候选版本到稳定版本的逐项变化。

## 从旧的嵌入方式迁移

- 使用 ESM 入口 `lumina-report-sdk`，同时导入 `lumina-report-sdk/style.css`。
- 在 DOM 挂载完成后调用 `createSpreadsheet`，给容器设置明确高度；不要在服务端渲染阶段创建实例。
- 组件卸载前调用 `grid.destroy()`。React 使用 `useEffect`，Vue 使用 `onMounted`/`onBeforeUnmount`；不要在 render 或模板计算期间创建实例。
- `onChange` 是变化通知，不是服务器保存。结构操作使用 `onStructureChange`，重命名使用 `onSheetRename`；保存时应明确记录工作簿版本。
- `import`、`export`、分页和数据源都返回 Promise；使用 `AbortSignal` 处理页面切换和用户取消，并忽略销毁后的结果。

## 从 0.x 到 1.x 的检查清单

1. 锁定 `lumina-report-sdk` 的完整版本，不使用 `^` 或 `latest`。
2. 用业务脱敏语料执行 JSON、CSV 和文档支持子集内的 XLSX 往返；遇到拒绝应显示给用户，不要静默降级。
3. 检查公式是否属于 [支持函数表](FORMULAS.md)，并为不支持的函数提供替代或导出前提示。
4. 按 [浏览器矩阵](BROWSER-ACCEPTANCE.md) 验证目标浏览器、剪贴板权限、中文 IME、刷新恢复和移动触控。
5. 把包内 `THIRD_PARTY_NOTICES.txt` 与依赖清单交给组织的许可审查；Apache-2.0 项目许可不替代第三方许可。
6. 升级前保存 JSON 快照；升级后先导入副本，再切换生产数据。

## 兼容承诺

CSV/TSV 单格长度在累积时执行 32,767 UTF-16 单元上限，不再等到分隔符后检查。转义双引号按一个内容字符计数，Emoji 按两个 UTF-16 单元计数；同时超长且引号未闭合的字段现在优先报告容量错误。有效文件语义不变。自动分隔符检测仍需扫描首条逻辑记录，但不会为检测复制整格内容。

文件读取取消：SDK 的 import(file, { signal }) 签名不变；内部 importFile 生成声明新增可选 signal，原单参数调用保持兼容。此函数不从包根导出，也没有新增包导出路径。取消现在会停止等待原始字节并跳过后续解析启动；已开始的原生读取、同步解析和 ExcelJS 解码仍不能中途终止。

分享链接导入：snapshot 内容按严格 UTF-8 解码，且工作簿校验成功后才进入共享副本模式。无效编码、Base64、空值或工作簿结构会显示错误并正常打开本地工作空间，不再把初始文档误当共享副本写入或覆盖本地活动文档选择。合法共享副本仍使用独立 ID；链接不是访问控制或云端同步机制。

文本文件编码：CSV、TSV、JSON 文件现在按严格 UTF-8 解码，损坏字节不再被静默替换成“�”。允许起始 UTF-8 BOM 和合法编码的 U+FFFD 字符；不自动猜测 GBK 或 UTF-16，请从原始数据重新导出为 UTF-8 后重试。文件读取错误与编码错误分别保留，失败不改变现有工作簿或历史。直接接收 JavaScript 字符串的解析 API 不涉及文件字节解码，此项不改变其契约。

XLSX 共享字符串引用必须是完整、非负且在字符串表范围内的十进制整数；允许前导零、显式加号及周围空白。空值、十六进制、二进制、小数和科学计数索引现在明确拒绝，避免底层部分解析导致文字错位或丢失。此项约束的是文件内部文本引用，不影响普通数字单元格支持的科学计数形式。

1.x 只承诺发布时 [支持矩阵](SUPPORT-MATRIX.md) 中已验收的 API 和文件子集。新增公共 API 会记录在 [API 稳定性](API-STABILITY.md) 和变更日志中；未列出的 Excel/SpreadJS 能力不属于兼容承诺。


XLSX 常量错误迁移：文件中没有公式的标准错误单元格（#N/A、#REF!、#NAME?、#DIV/0!、#NULL!、#VALUE!、#NUM!）现在导入为等价错误字面量公式，例如 value:'=#N/A'，因此 IFERROR 和依赖传播保持错误含义；原来静默转成普通文本的行为不再保留。普通字符串 '#N/A' 仍为文本。再次导出会包含字面量公式与错误缓存，故保持计算语义但不保留原文件“常量错误/公式”存储类别；JSON 保存使用相同公式表示。未知/空/重复值的常量错误明确拒绝，不降级。公式错误缓存本身不替代公式正文。若业务必须保留常量错误类别，本数据模型尚未提供该能力。


XLSX 值校验收紧：数字节点必须为完整有限十进制/科学计数写法，不再接受 12oops、0x10 等只被底层部分解析的内容；正负号、小数和指数及周围空白按数值处理。常量布尔仅接受 0/1/true/false（周围空白忽略），直接从原始 XML 读取，避免底层 parseInt 误判。重复 v/f 节点拒绝，缺少数值的样式空白格仍保留。已存在公式的缓存不是原始输入值，此检查不承诺完整 OOXML 校验或任意精度数字保真。导入失败保持当前工作簿和历史。


分页缓存迁移：pageSize 现在是请求上限，宽表按 maxPageCells 自动减小实际页长。依赖页号或偏移的宿主应读取 ReportChunkCache.pageSize 或 dataSourceState.pageSize；不要用传入的 pageSize 推算。新增 maxPageTextUnits 超限会拒绝整页，处理可重试错误后调整查询/分页参数，不再无限保留长文本。详见 SDK 文档的分页容量约定。


静态 CSV 流分块迁移：iterateCsvChunks/workbookCsvReadableStream 不再保证每块结束于行边界；超宽行会按字段边界分块，chunkRows 仍触发已完成行数的刷新。CSV 完整字节、换行和进度含义不变。宿主必须顺序写入同一流并在结束后解析，不能独立解析每块；取消应丢弃部分文件。


分页 CSV 现在默认拒绝单页累计超过 8,000,000 UTF-16 文本单元的响应。此前依赖巨大长文本页的调用方应减小 pageSize，或在 32,000,000 硬上限内显式设置 maxPageTextUnits；超限不截断。SDK 下载通过 ExportOptions.pagedCsv 配置。已有写入字节不代表完整文件，必须等待流成功结束，错误时丢弃部分输出。


REST 适配器改为流式限量读取 body，默认响应体上限 16 MiB、可配置 maxResponseBytes（最大 64 MiB）；超限拒绝并取消读取。自定义 fetcher 需返回标准 Response，不再依赖覆盖 response.json()。单页超过预算时调整分页或预算后重试，不截断返回。


REST 响应必须是有效 UTF-8。此前无效字节可能被替换成“�”并作为正常文本导入，现在整页拒绝，宿主应提示编码错误并修复服务端响应。合法编码的同一显示字符仍允许；不会根据文本外观猜测损坏。


XLSX 数组/数据表公式现在在导入前拒绝，以保留原文件计算语义；此前可能成功打开却把部分从属结果变成常量的行为不再保留。请保留原文件，不要把手动删除数组标记当作等价转换。普通与支持的共享公式保持逐格公式导入，SDK 导入失败保留原工作簿和撤销历史。


XLSX 共享公式不再使用底层的文本替换式展开，避免把字符串 "A1" 或工作表名 'A1' 错改为 A2。缺失/重复主公式、无效共享编号及组范围越界现在明确拒绝。导出仍使用逐格普通公式，不保留共享压缩表示。


XLSX 共享公式展开现在有跨表 8,000,000 UTF-16 单元的累计公式上限（含每格前导 =）；单格上限仍为 32,767，但提前到 ExcelJS 解码前检查。超出容量明确拒绝，需在保留原文件的前提下分拆业务工作簿，不能通过删减公式文本继续导入。

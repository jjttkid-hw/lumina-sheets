- 新增 10 项排序规划、27 项公式平移和 21 项 SDK 排序测试。覆盖多关键字稳定顺序、空值、隐藏轴、稀疏整行移动、输入隔离、引用越界、配额拒绝、只读/分页限制、批量验证、撤销/重做、回调重入及无操作保留重做记录。
- 回归发现并修复：排序可能保持公式文本不变，却因同行输入移动而改变计算结果。目标验证现覆盖位置变化行中的已存储单元格，使用整批候选数据求值；拒绝时不改数据、缓存和历史。此处不是全表持续约束检查。
- 独立生产 SDK 的“多列排序”示例按 B 列区域升序、E 列金额降序排序，实际移动 **4 行**。可见记录依次为 **项目-2、项目-3、项目-20、项目-1、项目-10**；两个金额 1,200 的记录保持原相对顺序。隐藏 A4 仍为“内部项目”，E4 的 `=C4*D4` 仍为 **50**。
- 浏览器实际读取排序后 E2 为 `=C2*D2`，结果 **1,200**；E8 的 `=SUM(E2:E7)` 为 **4,350**，包含隐藏行。一次撤销恢复 A2“项目-10”、E2 **600**，重做恢复“项目-2”，当前选区保留。
- 重复相同排序提示无新增撤销记录；将起始行设为 1 明确拒绝与冻结前导行相交。随后一次撤销仍直接恢复原始首行，确认这些操作没有插入历史记录。
- 最终生产 SDK “检查空闲绘制”显示 **1 秒内额外绘制 0 次**，浏览器日志未见 error/warn。这是单环境空闲采样，本轮没有重新采集百万格耗时，也没有排序延迟或跨浏览器性能认证。

排序当前用于静态表，单次最多 100,000 行、8 个排序键及 100,000 个最终单元格补丁，扫描已有数据同步执行。默认隐藏行留在原坐标，文本筛选不缩小显式范围；冻结/合并范围明确拒绝。行高、规则及外部公式引用仍绑定原坐标，移动公式按真实行差平移，跨行公式结果可能改变。完整行为见 [SORT.md](SORT.md)。完整 Excel/SpreadJS 兼容、商业许可审计及发布认证仍未完成。

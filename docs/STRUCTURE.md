# 行列结构编辑

`planStructureEdit(workbook, sheetId, edit)` 生成插入或删除行列后的候选工作表：

```ts
interface StructureEdit {
  axis: 'row' | 'column';
  kind: 'insert' | 'delete';
  index: number;
  count: number;
}

const plan = planStructureEdit(workbook, sheet.id, {
  axis: 'row',
  kind: 'insert',
  index: 2,
  count: 3,
});
// plan.sheets：候选工作表数组
// plan.changedSheetIds：实际改变的工作表 ID
```

索引从 0 开始：插入在 `index` 之前进行；删除从 `index` 开始的 `count` 行或列。可以在工作表末尾插入，不能删除全部行或全部列，结果不能超过 1,048,576 行和 16,384 列。分页数据源为只读，拒绝结构编辑。

规划函数不修改输入，失败时不留下部分更改。改变的工作表是独立副本，未改变工作表可以复用输入引用。调用方负责将候选整体提交、更新计算器和历史；不要在提交前修改返回的共享未变工作表。此模块不会自行触发 UI、持久化或事件。

## 单元格与公式

只枚举已存储单元格，移动目标工作表中的坐标，删除范围内的单元格会移除，不创建空白单元格。新插入的行列默认没有值、样式或指定列宽。

结构编辑还会扫描整个工作簿中的已存储公式，调用 `rewriteFormulaReferences` 更新本表和跨表引用。绝对引用中的 `$` 不阻止行列结构移动；删除的引用变成 `#REF!`，部分删除的范围收缩，公式字符串中的文字保持原样。不支持的引用语法或引用溢出会拒绝整个操作，不静默改变公式含义。

这是结构操作时的全簿存储扫描，与单格热编辑的依赖索引失效不同。工作量与已存储单元格、公式文本及元数据规模有关，不与逻辑矩形格数成正比；改变的工作表副本仍可能占较多内存。没有为百万逻辑行创建密集数组或逐格布局。

## 范围变换

`transformRange(range, edit)` 返回变换后的零基闭区间或 `undefined`，规则用于合并、输入约束和宿主的条件格式：

- 在范围起点之前或恰好起点插入，范围整体后移。
- 在范围内部插入，范围扩张以包含新增行列。
- 在范围末尾之后插入，不改变范围。
- 部分删除让范围收缩；完全删除让范围消失。

`transformPosition(position, edit)` 变换编辑轴上的一个坐标；坐标在删除区间内时返回 `undefined`。这两个工具都会校验坐标与 Excel 边界。

合并区域使用上述范围规则。完全删除的合并移除，缩成单格的合并也移除。删除合并锚点时不会自动搬运其已删除内容；保留区域只保留实际未删除的存储值。

## 布局与规则元数据

列操作同步移动或删除指定列宽，新增列使用默认宽度。冻结行与重复标题是从第 1 行/列开始的前缀：插入位置在前缀内部时增加数量，恰好在前缀末端时不增加；删除前缀中的行列减少数量。

手动分页是位置边界。插入发生在边界之前或相同位置时边界后移；删除覆盖边界时折叠到删除起点。重合边界去重，落到起点、末尾或重复标题内部的冗余边界移除。其余分页仍需满足打印参数校验，不可跨越合并区域；冲突时操作失败。

工作表 `dataValidations` 中未指定 `sheetId` 的规则按其存放工作表处理；显式 `sheetId` 按对应目标处理，即使规则存放在其他工作表。受影响范围移动、扩张、收缩或移除，列表和阈值不变。规则超出当前已用区域不代表没有约束；如果变换后超出 Excel 边界，操作会拒绝。

条件格式不在 Workbook 的持久化模型里，由 SDK 使用同一 `transformRange` 规则更新。外部批注、宿主自定义坐标对象、图表和未建模的 Excel 对象不会由此模块自动迁移。

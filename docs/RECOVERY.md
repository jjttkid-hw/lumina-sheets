# 崩溃后的本地恢复备份

副本命名遵循工作簿的 200 UTF-16 单元上限：为“（恢复副本）”预留完整空间，超长原名只缩短前缀且不拆开 Emoji 代理对。普通副本和共享副本也采用同一规则，避免重新加载时丢失副本标记。原工作簿名称不修改。

恢复 JSON 文件使用严格 UTF-8 解码，支持起始 BOM；损坏字节在打开恢复目录前明确拒绝，不会静默替换成“�”后生成副本。合法编码的“�”、中文和 Emoji 保持。读取失败或取消不写入工作簿，可以修复文件后重试；不自动猜测 GBK/UTF-16。结构有效但内容早已被外部软件替换的文件，无法据此恢复丢失信息。

工作空间渲染失败时，可先点击“下载恢复备份”。文件读取当前持久化适配器中的工作簿、可见待写补丁、批注与历史版本，并保留 `lumina.*` 浏览器本地存储原始条目。IndexedDB 与内存后备均通过同一适配器读取；仅内存会话刷新后可能丢失，请先保存下载文件。

文件格式为 `lumina-recovery`，版本 1：

- `records[]`：每项包含 `workbook`、`comments` 和 `revisions`。
- `damagedWorkbookDirectory`（可选）：主存储返回非列表目录时保留可 JSON 序列化的原值，`records` 保持空列表并附带警告；不将字符串拆成工作簿条目。旧版/回收站仍可从 `legacy` 恢复。该字段供进一步救援，不自动解释成工作簿。
- `legacy`：旧本地条目的原始 JSON 文本，包括设置和回收站；不包含其他应用的存储。
- `complete` / `warnings`：某一部分读取失败时仍保存其他成功部分；失败的批注或历史为 `null`，不能视为“本来没有数据”。

0.28 起可在工作空间点击“导入”，选择恢复备份 JSON，再从列表选择一本工作簿，点击“恢复为新工作簿”。导入器逐本校验所选快照；损坏记录会显示错误，仍可改选其他记录。恢复生成新的工作簿及工作表 ID，验证规则引用同步重映射，名称增加“（恢复副本）”。原工作簿不被覆盖，恢复后使用既有保存队列并显示保存状态。取消选择不写入。

恢复入口最多读取 20 MB 文件、所有来源合计 1,000 条目录记录，所选快照仍受普通工作簿容量与结构限制；备份下载没有同等大小限额，因此超大的救援包需要先提取 `records[i].workbook` 为单独 JSON。SDK 的 import 仍只接收单工作簿，不接收整个恢复包。

本次恢复包含工作簿快照内的表格内容、公式、样式和规则。目录自动解析 `legacy` 中 `lumina.v1.workbooks` 和 `lumina.v1.trash` 的原始 JSON 列表，并标注“工作空间 / 旧版文档 / 回收站”来源。即使 `records` 为空也可恢复这些快照；同 ID 的不同版本分别保留，不自动去重。损坏列表显示目录警告，其他来源仍可选择；损坏单条快照在选择恢复时明确报错。请保留原文件中的损坏内容以便进一步恢复。`records[].revisions` 和 `legacy` 中 `lumina.v1.history.*` 的工作簿快照也会列出，标注“历史版本 / 旧版历史”、版本名称和时间；缺失展示元数据使用占位文字，完整校验仍在选择恢复时进行。历史快照同样计入合计 1,000 条限额。批注与历史列表仍不合并回写，新工作簿只包含所选快照。面板会明确说明这些边界。不要清空原浏览器数据，直到所需文件已被独立打开检查且已保存。

读取不是跨存储的事务快照，后台仍可能有完成中的写入。尚未进入适配器的工作空间保存队列内容、未提交的输入草稿、已经丢失的数据无法保证包含。`complete: true` 只表示本次读取及已执行的目录/辅助元数据检查没有报告失败，不代表所有快照已通过完整工作簿校验，不是断电恢复或企业备份认证。若存储损坏或浏览器拒绝访问，文件会标明缺失；整个生成失败时界面提示重试。

备份包含用户工作簿正文，应由用户自行保存，不会自动上传。组件卸载后不继续触发下载；重复点击只启动一次读取。真实浏览器下载与故障恢复仍待验收。


分页工作表的恢复副本仍保留 dataSource 标记，不会因为本地恢复变成完整静态数据。工作空间会提示内容可能未完整加载，并保持网格及公式栏只读。需要在原数据源导出完整文件；备份的 complete 标志仅描述读取和已执行的结构检查是否成功，不能证明分页远端数据已完整保存。


启动时主目录不是列表，或存在损坏工作簿且没有可打开的有效文档时，停止进入工作空间并提供备份/重试，不保存旧本地副本覆盖主存储。部分工作簿损坏时仍可打开其他有效文档，顶部持续显示未打开数量和备份入口。先保留备份再修复存储；修复后的重试重新读取主目录。此保护发生在持久化读取之后，不能保证此前旧版迁移未写入，也不表示跨存储事务或所有备份快照已完整校验。


旧版迁移对工作簿、批注和历史分别采用“仅补入不存在的键”。主存储已有的记录（含空辅助列表或损坏记录）保持原样，不根据更新时间猜测覆盖；旧版本仍保留在原 localStorage，可通过恢复包独立提取。IndexedDB 的存在检查和写入使用同一写事务；原生事务及多页面迁移仍需浏览器验收。


旧版列表存在重复工作簿 ID 时，自动迁移仅取首条，内存与 IndexedDB 保持同一规则。不会按时间猜测哪个版本正确；原始列表不改写，恢复包目录仍分别列出同 ID 的所有版本供选择。


主存储目录含 null、标量快照或缺少 workbook 字段的行时，批量读取保留这些条目供校验/恢复，不因此中断其他有效工作簿及其日志重放。不能据此承诺任意日志损坏或无法序列化数据都能恢复；所选快照仍需完整校验。


多页面首次迁移时，在读写事务内重新检查迁移标记；此前的只读检查仅用于快速跳过。若另一页面已完成迁移，不再写入旧工作簿或辅助记录，避免将迁移后删除的记录重新带回。Chromium、Firefox、WebKit 已通过两个页面同时打开旧数据的原生 IndexedDB 迁移检查；这不证明突然断电或浏览器进程崩溃时的存储一致性。


批注/历史的“未存储”与“已存储但损坏”分别处理：不存在的键返回空列表；已有 null、标量或缺少载荷字段的记录保留原值，交由界面元数据校验报错并阻止覆盖，备份标记为部分且保留原材料。内存与 IndexedDB 读取遵循相同规则。


工作簿尚在保存、保存失败、仅内存会话，或批注/历史仍在写入时，刷新/关闭页面会通过 beforeunload 请求原生离页提示；最新持久化保存成功后解除。Canvas 编辑框与公式栏分别跟踪未提交文本，包括 compositionend 中的最终输入；一方清理不解除另一方的风险。提交、取消或编辑器卸载后清理对应标志。公式栏 Enter 校验失败保留草稿及风险，失焦校验失败按原契约恢复已存值并清理草稿风险，错误提示保留。浏览器可能要求用户先有交互，移动端/进程强制结束不保证触发；这不替代备份，也不能在离页时同步完成 IndexedDB 保存。草稿没有因此自动保存或加入恢复包；原生提示仍待真实浏览器验收。


新编辑日志使用独立 operationId，重试保留 ID；同序号不同编辑分别存储和重放，旧无 ID 日志仍按旧键识别。相同序号按 ID 确定性排序，并不证明用户操作的真实先后。此改动不解决并发全量快照覆盖、整理删除其他页面日志或协同冲突；多页面同时修改同一工作簿仍不能视为已支持的协同模式。


正常工作簿读取/日志重放失败时，备份会尝试 `rawStorage` 救援：分别读取工作簿、日志、批注、历史存储并保留内存中待写日志。该读取不迁移、不重放、不写回；单个存储读取失败有独立警告。内存材料采用 `{key,value}` 条目，IndexedDB 保留原行对象。原始工作簿可在目录中以“原始快照（未重放日志）”选择恢复，仍受合计 1,000 条及普通快照校验限制。它可能缺少后续编辑，不能冒充最新文档；原始日志保留供进一步救援，不自动重放。各存储读取不是同一事务快照。

# v2.0 产品路线与验收

目标是可嵌入、可验证的高性能 JavaScript 表格与报表 SDK。v2.0 是交付目标；当前仍是 0.29 开发线，不能通过改版本号替代功能完成或验收。npm 分发独立于产品验收，不阻挡 SDK 归档交付。

## 推进顺序

| 阶段           | 交付内容                                                 | 进入条件与验证                                                                                  |
| -------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 业务计算       | 不规则日期现金流 XNPV/XIRR；后续扩展统计、日期、查找函数 | 独立已知结果、错误语义、计算预算、跨表依赖、Worker、XLSX 往返、三引擎业务交互                   |
| 数据分析       | 静态数据透视与聚合配置、图表及导出策略                   | 编辑后重算、空值与错误策略、重复分组、确定排序、超额拒绝；不能把图片导出称为完整 Excel 图表兼容 |
| 报表设计       | 版本化模板、字段绑定与预览；更完整的打印与矢量 PDF       | 模板迁移、分页/重复标题、字体与文本布局、真实下载与打开对照                                     |
| 大数据编辑     | 有界查找/替换、后台计算与更细传输、结构编辑成本控制      | 大范围成员预算、撤销原子性、取消、销毁、旧结果隔离；使用目标设备测量，分别记录逻辑行与实存格    |
| 扩展与稳定交付 | API 迁移、框架生命周期、可访问性及部署材料               | 同一候选摘要绑定所有报告；复用 v1 平台、文件、许可验收门槛                                      |

动态数组、结构化引用和协作协议需要单独设计数据模型、错误行为与迁移契约，尚未实现。组织权限、认证、云备份与计费由服务端实现，不在纯前端 SDK 中虚构。

## 当前里程碑：实际日期投资回款

新增 XNPV/XIRR 和可编辑的“投资回款”示例。日期与现金流必须一一对应；错误不会通过忽略成员掩盖。XIRR 对当前折现金额归一化，限制迭代访问成员数量，避免无解大范围长时间反复扫描。具体支持域与限制见 [公式说明](FORMULAS.md#实际日期现金流)。

验收使用 2008-01-01 至 2009-04-01 的五笔现金流：9% 折现下净现值 2086.647602，内部收益率 0.373362533519；在示例中修改金额、撤销、修改日期后，Excel 导出再导入必须保留公式并重算。浏览器检查纳入现有 CI 交互套件。

## 当前里程碑：有界查找与批量替换

编辑器新增“查找与替换”弹窗，报表示例新增查找下一格、批量替换。SDK 提供 `findCells` / `replaceAll`，共享纯函数规划器；按行列顺序匹配已存储文字，可区分大小写、整格匹配、显式包含公式源码。支持空替换与字面符号，隐藏/筛选单元格仍纳入操作。

默认最多扫描 100,000 个实存格、32,000,000 个 UTF-16 字符、返回 100,000 处匹配；超额整批拒绝，不能悄悄截断。普通文字不能由替换意外变成公式。批量替换先检查所有数据规则，失败不改变工作簿或撤销记录；成功一次撤销、保留选区、重算依赖公式。局部富文本在文字改变后清除，单元格样式和链接保留。

当前为同步、单工作表的源文字操作，不查找数字、格式化显示或计算结果；分页数据需服务端查找。后台取消、跨表替换与索引搜索属于后续开发，不能将这次交付称为整个大数据编辑阶段完成。

## 稳定版本条件

沿用 [支持矩阵](SUPPORT-MATRIX.md) 与 [v1 验收计划](V1-PLAN.md) 的证据规则，并为每项新能力增加回归、真实应用语料和边界说明。新候选不能使用旧制品的摘要作为通过证据。原生 IME、真实屏幕阅读器、实体触控、跨设备性能和独立商业再分发复核仍需实际完成。

本路线尚未完成；透视/图表/设计器/矢量打印等条目不是现有功能承诺。每个阶段完成后更新实际范围与证据，再决定稳定版本。

## v3.0 首个里程碑：可编程透视分析

3.0 开始落地独立的数据分析层。新增 `createPivot` 与 `generatePivotReport`，支持 1–8 个行分组字段、可选列分类，以及最多 8 个指标的求和、计数、平均、最小和最大聚合。指标共享同一份原始记录状态，因此总计平均值按原记录计算，不会错误地平均各分组平均值；输入维度区分数字、文字、布尔值和空值。

透视计算默认限制为 100,000 条记录、10,000 个分组、256 个列分类、100,000 个输出单元格和 8,000,000 个维度文字单元。超限或数值溢出整批拒绝，不生成部分结果。`sort: 'label'` 使用稳定的确定排序；默认保留源记录首次出现顺序。SDK 的 `pivot()` 将分析结果安装为普通可编辑工作表快照，支持已有 XLSX 导出链路；它不是 Excel 原生透视缓存/透视表对象，源数据改变后需要重新生成。

报表示例增加“透视分析”布局，可选择区域、产品、月份和营收聚合方式，展示营收与记录数两个指标。3.0 后续将把此模型接入后台计算、可视化图表和版本化模板；协作协议、权限、云存储和计费仍不属于纯前端 SDK 的承诺。

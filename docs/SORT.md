# SDK 静态工作表排序

`sortRows(request)` 对当前静态工作表的显式行区间做稳定排序，移动这些行中的全部已存储单元格与样式。它不会只移动选中列，也不根据当前筛选或选择区域推断范围。

```js
const result = grid.sortRows({
  startRow: 1, // 零基坐标：从第 2 行开始，避开表头
  rowCount: 100,
  keys: [
    { column: 2, direction: 'asc' },
    { column: 5, direction: 'desc' },
  ],
  includeHidden: false,
});
console.log(result.movedRows, result.changedCells);
grid.undo(); // 一次撤销整次排序
```

公开类型 `RowSortRequest` 包含 `startRow`、`rowCount`、`keys` 和可选 `includeHidden`；每个 `RowSortKey` 包含 `column` 与 `direction: 'asc' | 'desc'`。返回的 `SortResult` 为 `{ movedRows, changedCells }`：前者是位置变化的行数，后者是提交的单元格补丁数量，包含值删除。已按要求排好序时返回两个零，不产生历史、事件、修改时间或重做记录变化。

## 顺序与值

- 按 `keys` 先后顺序比较，所有键相同的行保留原相对顺序。
- 公式排序键在移动前按当前工作簿计算值一次性求值，使用独立计算缓存；计划与拒绝不填充或失效实例的已有公式缓存。
- 数字按大小比较；文本按 `zh-CN`、数字片段自然排序、不区分大小写和重音比较。非空混合类型的升序为数字、文本、布尔值，降序反转该顺序；布尔值中 `false` 在 `true` 之前。
- 空单元格与计算结果空字符串固定排在末尾，升序和降序均如此。公式错误的显示字符串按文本排序，不提供 Excel 的完整错误值排序规则。

默认 `includeHidden: false`：持久化隐藏行保持原位，其他行只在剩余目标位置之间重排；显式 `true` 才将隐藏行纳入排序。隐藏列不会阻止其值成为排序键，也不会阻止其中的数据随整行移动。筛选与 `clipboardMode` 不改变显式排序范围；筛选结果会在值变化后更新。

移动的公式按源行到目标行的偏移平移相对 A1 引用，绝对引用保持不变，越界相对引用产生 `#REF!`。同一行内的相对引用会随整行平移；引用其他行的相对公式在排序后可能改变结果，最终显示的公式键不保证仍按数值有序。排序区域之外的公式及其他工作表对该区域的引用保持原坐标，不会自动追踪某条业务记录。移动公式中不支持安全重写的引用语法（例如结构化、外部工作簿、整行/整列或 3D 引用）会明确拒绝。此行为需要由宿主按报表用途选择，不是完整 Excel 排序引用兼容。

## 原子编辑与边界

排序计划不修改工作簿。提交前，目标单元格按完整候选批量执行已有输入验证；任何失败都拒绝整次排序，数据、历史、事件和现有计算缓存保持不变。成功提交进入一次可撤销事务，对每个受影响工作表各发一次 `onChange({ sheetId, changes })`，只触发一次订阅通知，无独立排序事件。排序及其撤销/重做保留当前范围选区；回调重入产生的新选择或加载的新工作簿不会被旧排序覆盖。

候选验证覆盖实际变更格及位置发生变化的行中已存储单元格，包括平移后公式文本相同、计算结果却因同行数据改变的情况。它不重新认证全表既有无效值，也不验证区域外的所有依赖公式；未存储且始终为空的目标不因此成为强制填报项。

行高、列宽、隐藏坐标、冻结行数、条件格式范围、输入验证和打印设置仍绑定原坐标，不随记录移动。单元格自身样式随数据移动。排序不改工作表尺寸，空单元格仍保持稀疏存储。

- 每次范围为 `1–100,000` 行，必须位于当前工作表内；排序键为 `1–8` 个不同的有效列，方向必须明确指定。
- 请求和键对象拒绝未知字段；无效参数为 `INVALID_ARGUMENT`。最多提交 `100,000` 个单元格补丁，超出时整次拒绝，不截断。
- 范围与冻结前导行或任意合并区域相交时明确拒绝，包括默认排除的隐藏行；请调整范围或先解除相关布局。
- 只读实例、绑定分页数据及持久化分页工作表返回 `READ_ONLY`。销毁实例返回 `DESTROYED`。目标输入规则不通过返回 `VALIDATION_FAILED`。

排序同步扫描已有数据并比较参与行，不为逻辑空白工作表创建密集单元格。排序键求值可能读取其他范围，仍受公式引擎执行限制；它不是百万实存数据的即时或后台排序保证。服务端分页数据应由数据源排序后重新绑定。

## 内部链接目标

排序按来源行到目标行的映射更新已保存的单 A1 内部链接，包括同表/跨表、绝对地址与带引号的表名。链接先随记录移动，再调整其目标；表内未移动格以及其他表里的链接也参与目标更新。本地未限定地址属于链接所在工作表。外部 URL、范围、名称及其他未支持目标保持原文。隐藏行默认不移动，指向隐藏行的地址保持原位。

所有链接变化和排序记录作为一次事务提交和撤销，累计最多 100,000 格。关联表只读或候选验证失败时不提交。SDK 对每个受影响表发送一次 onChange，首个回调前全部数据和历史已提交；回调引起新修改或销毁时停止旧事务后续通知。changedCells 包含关联表变更。工作空间将多表补丁一次交给保存队列；持久化成功仍需等待保存状态。

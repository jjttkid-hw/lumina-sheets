# 工作空间填报与保存

v0.13 主工作空间与 SDK 共用整批候选值校验。公式栏、Canvas 单格输入、粘贴、填充、清空，以及合并时的值迁移在任何存储和历史变更前完成校验。整批公式看到全部候选值（包括删除和跨表依赖），失败时不提交部分单元格，不创建撤销记录，不改变计算缓存。

规则检查以本次提交的地址为范围。同批再次提交原文本公式时，仍检查其候选结果；完全没有变更的操作不新增历史。没有编辑的依赖格不会成为持续强约束，导入的既有内容和历史撤销也不会重新强制校验。v0.15 可从工具栏“数据验证”配置规则，也可通过 SDK 或导入受支持的 JSON/XLSX 规则；操作和边界见 [规则编辑器](WORKSPACE-VALIDATION.md)。

公式栏按 Enter 提交；失败保留草稿与输入焦点，并显示具体地址和规则。修改后可重试；Escape 放弃草稿。失焦提交失败时恢复已存值并显示错误，切换单元格清除旧草稿，防止把旧输入写入新选区。中文输入法确认不触发提前提交。

工作空间限制为每本 100,000 个存储单元格、每表 100,000 行和 256 列、单格文本 32,767 个 UTF-16 代码单元。配额使用最终批次计算，允许同批删除和新增抵消；含合并表的扩展仍遵守 100,000 格布局限制，保证当前导入格式可接受。SDK 逻辑坐标上限不因此改变。

JSON 文件允许单独使用小写或带 `$` 的地址，导入后统一为标准 A1 地址；同一表中多个键指向同一格（如 `A1` 与 `$A$1`）会明确拒绝，即使值相同也不合并。重复的非空工作表 ID 同样拒绝，不自动猜测活动表或规则归属；缺失 ID 仍可生成。这些检查也用于恢复备份的工作簿校验及 XLSX 导出前校验，不改变编辑批次中同一地址取最终提议值的契约。

## 自动保存

创建、导入、新增工作表、重命名、收藏、切换活动表和历史恢复写工作簿快照；普通单元格及布局写补丁。两种操作经过一个顺序队列，后续补丁只有轮到它时才进入存储，防止旧快照清除新编辑。保存任务入队时捕获副本，不读取以后可能变化的数据。大批补丁等待所有写入完成，超过 500 条自动触发写入也不会漏掉尾部。

界面等待本地数据恢复后才开放编辑；“已保存到本地”仅在最新队列完成且使用 IndexedDB 时显示。失败任务保留在队首，后续写入排队等待；点击“重试保存”或按 Ctrl/Cmd+S 会重试并保存当前工作簿。若浏览器只能使用内存，显示“仅保存在本次会话”，需要导出文件备份。回收站仍使用浏览器本地存储保留可恢复副本，已归档工作簿不会因基础快照仍存在而回到主列表。

当前队列属于单页面实例，不是多标签页冲突协议；未完成写入时关闭页面仍可能丢失未保存的更改。旧版本已经丢失且没有任何快照、文件或历史的内容无法由升级恢复。工作空间仍有结构操作快照、统计扫描和编辑时配额计数，不用于证明百万实存格热编辑性能，也不等于云端同步或企业备份服务。

## v0.17 日志恢复与失败重试

打开工作簿时，日志按序号排列并整批回放；每张被单元格补丁修改的工作表最多复制一次单元格索引。元数据补丁不枚举单元格，未修改的表不参与复制。重复地址、删除后新增、多表交错和元数据更新仍按原始顺序生效，避免批量粘贴留下大量日志后重复复制整张表。

内存后备存储的单本/全部工作簿读取都返回隔离副本，修改读取结果不会污染已保存内容。正在写入的补丁仍计入待保存条数，并参与本实例读取；写入失败后回到待保存队首，保留原序号，随后排入的编辑保持在其后。显式重试不会把失败批次误当作保存成功。工作空间顺序队列仍负责快照与补丁的先后关系；独立调用存储适配器时，不应并发替换快照和提交补丁。

内部 `PatchHistory` 也使用整批回放，返回的事务与内部历史隔离；回放抛错不弹出历史记录。v0.17 时主工作空间仍为快照历史，v0.18 的变化见下节。日志没有自动压缩或跨标签页协调；故障测试使用受控 IndexedDB 边界，真实浏览器崩溃/断电恢复未验收。

## v0.18 混合撤销历史

普通单元格、批量粘贴、填充、排序、规则及布局修改，仅捕获所改地址和元数据字段的前后值；不为历史扫描或复制整本工作簿。整批操作仍是一次撤销，撤销和重做经同一个保存队列提交补丁。重复地址的原值只捕获一次，撤销尺寸扩展时同时恢复原尺寸与单元格。

新增工作表、工作簿重命名和手动版本恢复仍保留快照，与补丁记录在同一条最多 60 步的历史中交错。切换工作簿清空当前历史。无变化和校验失败不清空重做；新的成功编辑清空重做。补丁撤销保留当前活动工作表、收藏等不相关工作簿状态；快照恢复仍按整个历史版本恢复。

历史存储的减少不代表编辑全链路恒定开销：候选规划与补丁回放仍需浅复制受影响表的 cells 索引，工作空间仍进行配额计数；数值修改仍触发公式扫描与计算调度。历史在刷新后不保留，保存日志用于恢复当前内容而非跨会话撤销。尚未采集新的端到端耗时或峰值内存基准。


## v0.19 按计算输入调度

列宽、行高、隐藏行列、冻结、规则、既有单元格样式，以及工作簿名、收藏和活动表修改，在公式输入不变时复用同一个计算来源和版本；这些操作不重新扫描公式目标、不发送新的 Worker 请求，也不清空同步求值缓存。规则与布局的补丁撤销/重做采用相同判断。进行中的计算可以在这些修改后正常返回。

普通单元格补丁仅比较所改地址的值和存储存在性，不枚举整表来判断计算是否失效。单元格值、公式文本、表名、表尺寸、表顺序或数据源改变时使用新版本；没有完整补丁信息的单元格集合替换保守地重新计算。导入或快照恢复即使保留原工作簿 ID，也按新的内容来源处理。计算结果和所属版本一并保存，旧请求晚到时不能覆盖当前数据；后台结果不可用时使用当前版本的同步求值器。

每表最多收集 25,000 个公式目标，达到上限后不再读取后续单元格值；不再先构造完整条目数组。超出目标上限的公式仍由同步渲染求值器按需读取。无公式工作簿不发起计算请求，因此不为计算复制传输整本工作簿。

这是减少无关计算的工作空间优化。v0.29 在 Worker 传输边界按不可变工作表复用值快照：首个请求发送各表值，后续请求只发送单元格字典或尺寸发生变化的表；Worker 校验基准请求 ID、工作簿 ID、表目录和替换表，异常时丢弃缓存并从完整快照重新开始。后续小批量值补丁进一步减少变化表的传输量，见末节。它仍会扫描公式目标及变化表，样式/规则/分析可能产生其他成本；这不是依赖增量求值或协同协议，不承诺百万实存单元格编辑时延。


## v0.20 后台计算队列

主工作空间将计算运行时设为 `queueMode: 'latest'`。后台最多有一个已发送请求，以及一个仍在主线程的最新候选；连续编辑替换尚未发送的候选，被替换版本以 `AbortError` 结束，不进入 Worker 的结构化复制和计算。候选引用不可变工作簿，在等待期间不另行深复制，调用方须保持工作簿和目标数组不变。

数值、工作簿或表结构变化后，旧计算的 AbortSignal 被取消；公式全部删除或组件卸载也会清理旧请求。布局、样式和规则修改仍沿用 v0.19 的等价计算来源，因此不会取消有效的计算。已发送请求不能打断 Worker 内正在执行的同步公式代码：取消立即释放主线程等待者与监听器，但保留运行槽位直到对应消息返回，随后仅发送最新候选。前台继续用当前同步求值器提供尚无后台结果的单元格值。

运行时按请求 ID 路由消息，并验证计算版本；未知、重复和过早到达的候选消息不会结束其他请求。后台求值错误或发送失败拒绝相应请求后允许继续调度。Worker 错误或消息解码失败会拒绝全部等待者并终止 Worker；v0.29 后续修正为新请求到达时重新创建 Worker，失败则拒绝请求，不把整批后台计算改到主线程。销毁会清理运行与待发送请求、事件监听器，并拒绝后续调用。默认的 `all` 模式仍保留逐请求行为，此运行时不是 npm SDK 的公开接口。

v0.20 未提供执行超时，Worker 不回应且没有错误事件时会一直等待；v0.21 的超时恢复见下节。v0.29 后续增加了小批量值补丁，但尚未提供公式内部的协作中断，已发送的大计算仍可能延迟最新后台结果。无 Worker 时不会合并同步调用，也没有浏览器输入延迟或峰值内存的新承诺。


## v0.21 计算超时恢复

工作空间显式设置 `timeoutMs: 30_000`。每个请求在实际发送时启动超时计时，尚未发送的候选不计时；在后台执行中被取消的请求保留计时，防止无响应任务永久占用唯一运行槽位。完成、发送失败、Worker 故障或销毁会清理对应计时器。

到期仍未返回时，终止旧 Worker 并断开其消息处理器。旧 Worker 上仍在等待的请求以 `TimeoutError` 结束；已取消请求保持原来的 AbortError。最新且未取消的待发送候选保留，在新 Worker 上仅发送一次，并从发送时获得自己的完整时限。旧 Worker 的迟到消息或错误无法结束新请求。没有候选时不立即创建 Worker，而在下一次新计算时重建。

超时任务不会自动重试；新 Worker 上的候选也超时时，同样结束请求，没有新候选就停止，不形成定时重启循环。若重建失败，保留候选被拒绝，后续新请求可以再次尝试创建 Worker；这条超时恢复路径不会将整批计算改到主线程执行。界面原有同步按需求值仍负责显示尚无后台结果的单元格，复杂可见公式本身仍可能有成本。普通 Worker 错误现在同样在下一次请求时重建，见下文；首次启动时不可用的同步回退语义保持不变。

内部运行时支持 `timeoutMs: 0` 显式禁用保护；仅接受 0 到 2,147,483,647 的整数毫秒，默认 30,000。默认 `all` 模式中，各已发送请求有自己的期限；任一请求超时需要终止共享 Worker，因此其他已发送且未完成请求也会被拒绝。此运行时仍不属于 npm SDK 公开接口。

计时器依赖主线程事件循环，不能抢占主线程上的结构化复制或同步求值；浏览器后台节流、系统休眠与繁忙主线程可推迟定时回调。合法但超过时限的大计算也会终止，需要在接入策略中权衡时限。当前未采集真实浏览器超时恢复、输入延迟或峰值内存数据，不等于 30 秒硬实时 SLA。


## v0.22 选区与首页统计

状态栏的计数、求和和平均值不再对每次小选区变化枚举整张表。不超过 4,096 个逻辑单元格时直接检查选区坐标，仅对实际存储的格求值；超过该阈值时遍历稀疏存储，跳过范围之外的格，不展开空白网格。反向选区规范化并裁剪到当前表尺寸。沿用工作空间规范 A1 存储地址，不统计继承属性。

统计仍使用公式计算值：空字符串不计数，文本、布尔和错误值计入计数，求和与平均值仅包含数字，零和负数保留。隐藏行列和合并区域中的存储格仍按坐标参与，未改为“仅可见单元格”统计。求值器与当前计算输入来源共用缓存；后台结果返回不会导致选区重新统计。

首页的非空格数与记录行数合并为一次稀疏遍历，结果按当前表数据来源缓存；财务汇总按计算输入和活动表缓存。纯列宽、布局、规则、既有格样式与收藏变化复用结果，选择相同坐标的新选区对象也不重复计算。值变化、撤销重做、导入新内容和跨表依赖变化通过计算版本更新；切换活动表使用当前表 ID，而不是缓存来源中可能较早的活动表字段。

首页沿用原始值口径：公式即使返回空字符串也属于非空存储内容，第一行视为表头，不计入记录行数；状态栏按求值后的值统计，二者口径不同。没有将独立数据看板改为增量分析，也未消除数值修改后的财务扫描、编辑配额计数或复杂公式求值成本。大选区遍历仍与存储格数量有关；阈值不是浏览器时延保证，本轮未采集新的端到端性能数据。


## v0.23 文件操作先后关系

主工作空间导入是新增独立工作簿，不覆盖当前正在编辑的原工作簿。连续选择多个文件时，只有最后选择的导入可以新增、保存和切换当前工作簿；旧文件迟到的成功或失败不改变界面。卸载后不再提交导入。重名 ID 按完成时的当前列表生成独立副本，避免异步闭包使用过期列表。文件操作忙碌状态按未结束操作计数，某个操作提前结束不会解除其他操作的忙碌状态。

这与 SDK 的替换式导入不同：SDK 导入期间成功编辑会取消导入，见 [API-STABILITY.md](API-STABILITY.md)。两种路径都不保证底层解析立即停止，工作空间也尚无可视化取消按钮。


## v0.27 行列结构编辑

工作空间工具栏的“行列”打开插入/删除面板。默认使用选区的起始行和行数，切换到列后使用选区列范围；反向选择会正规化。输入一基位置与数量，插入发生在指定位置之前，末尾后一位可追加；删除发生在指定位置开始，至少保留一行/列。

操作范围使用原始坐标，隐藏行列也参与移动，筛选不缩小范围。结构规划器调整存储格、跨表公式、支持的合并/规则/行高/列宽/隐藏/冻结/打印元数据。候选工作簿通过完整文件层校验后才提交，因此工作空间仍受 100,000 行、256 列、100,000 存储格及合并布局等限制，不能套用 SDK 更大的逻辑尺寸。

一次成功操作写一个工作簿快照，进入既有串行保存队列和快照撤销历史。存储失败仍显示原有保存失败状态并可重试；失败的结构规划/校验不修改内容、不排队写入、不新增历史。删除格的引用会变为 #REF!；撤销/重做恢复整次结构变化，选区落在操作起点并限制在新尺寸内。

批注仍绑定坐标，不随单元格移动，面板明确展示这一限制。当前没有新增批注随结构移动的原子持久化契约；不据此宣称完整 Excel 行列语义。历史快照可能同时恢复当时的视图/收藏状态，沿用已有快照历史语义。

新增 3 项 App 处理器回归覆盖跨表公式与布局/规则移动、一次保存/撤销重做、超限失败原子性和删除引用；9 项表单处理器回归覆盖反向选区、行列切换、非法数量、追加、整轴删除拒绝、错误更正及取消。此为 hooks/存储边界替身测试，非真实浏览器交互证明。


## v0.28 快照保存提交边界

持久化适配器在快照调用时复制输入并记录补丁序号边界，成功提交后才移除被覆盖的旧补丁；写入失败仍可读取/重试原补丁。调用后新增的编辑保留，快照事务按调用顺序执行，并与已开始的补丁刷新协调。批量输入先全部复制，复制失败不部分改变内存存储；IndexedDB 事务准备阶段同步抛错时主动 abort。close 等待已排队快照再刷新补丁。

成功的快照是显式替换基准；重试旧快照仍意味着替换重试调用之前的内容，调用方应使用现有串行保存队列或最新完整快照。此实现不提供多标签页冲突合并；浏览器配额、版本切换和关闭窗口时机仍需实机测试。


## v0.29 Canvas 编辑会话

编辑草稿绑定当前会话编号、工作簿/工作表 ID、单元格字典、尺寸和计算/渲染修订。外部替换数据、结构或修订变化、改为只读、取消或卸载后，迟到的输入/失焦回调不会写入旧草稿。单元格字典或 SDK 渲染修订变化会取消尚未提交草稿，即使变化发生在其他单元格；这是一项保守的数据一致性策略，不支持协同草稿合并。

输入变化同步更新当前草稿引用，即使 React 尚未再次渲染，立即失焦也读取最新文本；重复失焦不会重复提交。输入法正在组合，或 Enter 的 native keyCode 为 229 时不提交。现有输入约束失败会保留编辑器；真实中文输入、焦点和事件时序仍需浏览器验收。

组合过程中发生失焦时，公式栏与 Canvas 延迟到 compositionend，读取结束事件中的最终文本再提交；不会先保存拼音中间态。公式栏使用编辑轮次隔离回调，从 A 切到 B 再回到相同值的 A，也不会接受旧组合事件。此行为已通过处理器回归，尚未取得操作系统输入法的浏览器验收证据。

## v0.29 批注读取与保存

批注读取成功后才允许新增或标记解决，读取失败显示重试入口。保存期间禁用编辑与重复提交，成功后更新列表；失败保留已确认列表与输入，用户可再次提交。关闭再打开面板不会打断正在进行的保存；切换工作簿再返回会等待此前写入结束后读取，旧面板回调不能提交到新会话。

批注尚未接入工作簿撤销历史或结构编辑的联合事务，仍绑定原始坐标。切换工作簿清空未提交草稿；此流程不提供跨标签页冲突合并，也不能保证页面在保存完成前关闭时不丢失修改。真实浏览器存储失败与交互仍待验收。

## v0.29 手动版本确认与恢复

版本历史读取成功后才允许新增恢复点；读取失败可在面板内重试。保存截取点击时的完整工作簿，保存成功后才加入可恢复列表，最多保留最近 20 个版本；失败不提前移除旧恢复点，可重新保存或导出文件。重新保存截取重试时的内容，不承诺保留失败那次点击的快照。

写入期间禁用重复保存与恢复。关闭重开面板不会发起旧列表读取，切换工作簿再返回会等待原写入结束再读取；旧回调不提交。恢复前验证快照内容和工作簿归属，失败不改变当前数据或撤销历史；成功恢复仍可一次撤销。工作簿的自动保存状态继续负责恢复后的持久化确认，版本面板的成功提示只表示恢复点本身已写入当前存储后端。

本地版本不包含批注，不提供跨标签页冲突合并；内存后备模式仍不耐刷新。真实 IndexedDB 故障、刷新与浏览器操作仍待验收。

## v0.29 按工作表复用计算传输

工作空间启用 `reuseSheets` 后，计算运行时首次为某个工作簿发送完整的工作表值快照；后续候选只发送单元格字典、名称或逻辑尺寸变化的工作表，并保留其他表在 Worker 中的值快照。样式、列宽、隐藏和打印元数据不进入计算传输，因为它们不改变公式输入。

每条消息带有工作簿 ID、表目录、基准请求 ID和当前请求 ID。Worker 只在基准仍是最近一次成功发送、表 ID 无重复且所有表都能重建时接受替换；不匹配、缺表或重复替换会拒绝计算，主线程清空发送缓存，下一条请求从完整快照重新开始。发送只在 `postMessage` 成功后提交为可复用基准，避免结构化复制或发送失败污染缓存。

最初这是按工作表的传输优化；后续小批量值补丁扩展见下节。它不是单元格级依赖增量、Worker 内部协作中断或跨标签页协议。表结构变化按新的目录和变化表重建；超时、Worker 错误和销毁会使发送缓存失效。真实浏览器结构化复制、输入延迟和内存收益尚未测量，不能把测试替身的消息数量当作性能 SLA。


## v0.29 小批量计算值补丁

同一工作簿、表名与尺寸不变时，发送器对变化的不可变 cells 字典进行值比对，仅发送新增、修改或删除的单元格；格式差异不进入补丁。空白存储格的新增和删除仍有区别。单表变化不超过 4,096 格时采用值补丁，超过阈值或表名/尺寸变化则发送完整表值；未变化表继续不扫描。阈值约束补丁数量，不是耗时承诺。

比对依据最后成功发送的快照，跳过的队列候选不会成为基准，因此合并连续编辑不会漏掉变化。发送失败、协议错误、超时重建后先发送完整快照。Worker 在副本上应用补丁后再提交基准；重复坐标、越界/非标准地址、未知工作表、与整表替换冲突或错误基准均拒绝。

这减少结构化复制的内容量，但主线程仍扫描变化表的存储格，最初 Worker 为变化表复制索引并重新创建求值器；后续依赖缓存复用见下节。公式目标仍整批发送。10,000 格改单格只发一格的回归是消息内容证据，不是浏览器吞吐、帧率、输入延迟或峰值内存证明。


## v0.29 Worker 依赖缓存复用

Worker 的计算会话现在保留受控求值器及依赖图。成功接收同一快照链上的值补丁后，先应用所有表的变化，再逐表通知单元格失效，最后读取目标。直接依赖、跨表和范围依赖沿用已有引擎的传递失效规则，独立公式可命中缓存；变化后的 IF 分支会更新订阅，错误修复同样触发重算。

完整同步、整表替换、表目录或顺序变化会重新建立求值器；每次计算请求也检查本地日期，跨日后重建以刷新 TODAY 及其依赖。没有新增午夜自动唤醒，因此没有新请求时不会主动刷新日期。非法传输在修改求值器前拒绝；超时终止 Worker 会同时释放会话缓存。

主线程依然扫描变化表，Worker 仍浅复制变化表的 cells 索引，完整目标列表仍被读取并返回。增量依赖计算减少公式正文执行次数，不保证整条编辑路径是常数开销。基准回归中 2,000 个独立公式修改一个输入只执行 1 个公式并命中 1,999 个缓存；这是实际引擎工作计数，不是真实浏览器延迟或商业 SLA。


## v0.29 线程故障后的按需重建

Worker error/messageerror 后终止旧线程、清理等待请求和传输基准；下一次新请求创建新线程并完整同步，不自动重放失败任务，不在无新请求时循环重建。重建失败明确拒绝，后续调用可以重试；已终止线程晚到的错误不影响新线程。首次启动就不可用、明确禁用 Worker 或 SSR 的同步路径保持原有行为；界面可见单元格的按需求值仍可能有同步成本。

队列回归覆盖两种故障、新请求重建、失败重试、完整快照和旧回调隔离；构造重建失败时使用不可读工作簿，确认不会偷偷触发同步计算。这是调度回归证据，尚非真实浏览器卡顿或故障恢复实测。

## 工作表重命名

工作表标签旁的“重命名当前工作表”入口可修改名称，显式跨表公式与单 A1 内部链接同时更新，并作为一次快照事务保存与撤销。名称不自动去掉首尾空格；长度、非法字符、保留名与重名先校验。大小写修改可接受，完全等名不新增历史。不支持的公式引用语法、公式重写超限或涉及只读分页表时整次拒绝。公式中的字符串、URL、未限定本地链接保持原文；验证、打印和批注依赖原工作表 ID，名称修改不更换 ID。SDK 对应方法为 `renameSheet(name, sheetId?)`，事件与历史约定见 SDK.md。关闭、成功提交或工作簿切换后迟到回调拒绝。此入口的真实浏览器焦点、输入法和窄屏验收尚未完成。


## 文件操作取消

工作空间处理文件时提供“取消文件操作”，会取消当前所有文件操作并保留已打开工作簿；迟到的文件解析/恢复包读取不能新增工作簿或打开恢复选择器。取消后的旧 Promise 不影响新操作的忙碌状态，也不弹出迟到成功/失败提示。新导入取代旧导入；页面卸载取消未完成导出。

导出捕获点击时完整工作簿副本并传入取消信号，CSV/PDF 在协作边界停止，XLSX/JSON 至少在下载前检查取消。文件读取、第三方解析或浏览器编码可能继续在后台结束，取消只是停止等待并禁止后续提交；同步工作无法被即时抢占。副本有全量内存成本。已开始的浏览器下载无法追回。实际按钮焦点、窄屏和浏览器下载仍待验收。


## 分页快照的后台计算一致性

工作表值传输保留 dataSource 的 kind/totalRows/pageSize；元数据数值变化时发送完整工作表替换，使后台依赖缓存重新建立。等值元数据对象不触发整表重传，普通样式变化仍不进入计算数据。静态→分页→静态切换即使 cells 没有变化也不能复用旧语义。

工作空间后台线程没有远端页读取器，因此分页引用为 #N/A，与同步引擎一致；不会把快照中的局部 cells 当成完整已加载数据。线程不会自动联网或抓取公式依赖页面。独立 Node 线程回归执行生产 worker handler，证明消息与引擎一致性，不证明真实浏览器帧率/延迟。

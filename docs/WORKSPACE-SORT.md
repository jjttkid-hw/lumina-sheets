# 主空间与 SDK 的行排序

主空间与 SDK 共用工作簿排序计划与候选验证逻辑。主空间对话框填写从 1 开始的“起始行”和“结束行”，包含两端；初始范围来自当前选区，用户确认后按该范围排序，筛选不会再缩小范围。界面要求至少两行，提供主要列和可选次要列，两列各自选择升序或降序，不能重复。底层支持最多 8 个键，SDK 使用零基 `startRow` 与 `rowCount`；详细类型见 [SORT.md](SORT.md)。

排序把参与行中全部已存储单元格和自身样式一起移动，远处列也包括在内；同值行保持原相对顺序。默认保留持久化隐藏行原位，可显式选择将隐藏行纳入。隐藏列照常随整行移动，筛选和剪贴板模式不改变排序范围。行高、列宽、隐藏坐标、打印设置和输入规则仍绑定原坐标。

排序键按移动前的计算值比较，公式求值和候选验证使用独立缓存，不污染当前编辑器的计算缓存。移动公式按行偏移平移相对 A1 引用，绝对引用不变；同一行引用随行平移，引用其他行的公式结果可能变化，排序后的公式结果不保证仍然有序。范围外与其他工作表的公式仍引用原坐标，不追踪业务记录。

提交前验证完整候选数据。除了实际变化格，还检查移动行中的已有单元格，防止公式文本未变但值已改变时绕过目标规则；任何失败拒绝整次排序。已排序范围为无操作。冻结前导行、相交合并格、不支持安全重写的移动公式、无效范围或超出配额都会明确拒绝。每次最多 100,000 行、100,000 个单元格补丁；分页数据源应在服务端排序后重新绑定。

主空间的一次成功排序作为一次工作簿更新，支持一次撤销恢复排序前数据，并可重做。v0.18 主空间排序采用补丁历史，撤销/重做以补丁保存；结构操作仍保留快照。共用排序规则和补丁历史不意味着主空间具有 SDK 大数据热编辑性能，不能据此承诺百万实存单元格即时排序。

候选验证不是持续的全表约束：范围外依赖和始终为空且未存储的目标不会因排序自动成为强制校验项。需要完整数据质量检查时，宿主应另行检查已有记录。此排序能力不构成完整 Excel 或 SpreadJS 排序兼容。

# 2026-09-21 三引擎性能实验室实测

本轮在真实 headless 浏览器运行产品性能实验室，属于本机测量与功能验证，未配置时延通过预算，不是性能 SLA、SpreadJS 对比或稳定版签署。

环境：Mac17,9、24 GiB 内存、15 逻辑处理器、macOS 26.7、Node v24.14.0、Playwright 1.57.0，1440×1000 浏览器窗口。未控制其他应用负载，未记录功耗模式。引擎串行运行；WebKit 26.0 不等同正式 Safari。

受测制品与上一轮交互验收一致：站点 SHA-256 `8dd656afc3289e02241e9126bd1b7ac4fa3dda8944f1daffae993aa0f8b9da57`，SDK SHA-256 `8371aab6f6db7e4aa6cf696c5c08f1b0c3b4d70c9bdc1a140fcd7a3eaf9bdabe`。执行前逐文件核对 HTTP 返回与 dist；本轮只新增测量脚本和证据，没有重建或改变受测产品代码。

两档分别填充 10,000×10 与 100,000×10 格，含 10,000 / 100,000 个公式；逻辑尺寸都是百万行×256列。每档完成 40 个目标视区（24 个填充区、16 个含空白边界的位置），本轮编辑前报告各保留 79 次真实绘制，不能等同全表密集滚动或 FPS。每档编辑只有 5 个样本，P95 实际为这 5 个样本最大值。数据准备和 Worker 计算均为单轮观测，不能估计稳定分布。

每轮原始 JSON、逐次绘制样本、编辑样本、Worker 首尾值及百万格截图见引擎子目录。before-edit 报告的首尾公式值为 5 和 50,000 / 500,000；连续将 A1 改为 10、20、30、40、50 后，after-edit 报告的首值为 54、末值不变，5 次编辑均被采集。截图在第二次计算后取得，所以其往返值可能与表中的首次计算不同。

## 功能检查

每引擎六组检查通过，页面异常及控制台错误均为零：两档实存数据及编辑/Worker 一致性，滚动采样取消及清空，范围基准取消，独立范围基准，重叠范围基准。范围基准每组 10,000 公式、30 次修改，归档后再次逐样本核对 checksum：独立范围为 40,001…40,030，重叠为 50,000…340,000；实际增量重算数分别为 1 和 10,000，全量均为 10,000。重叠情形没有宣称增量一定更快。

Firefox 首次运行在编辑后快速操作定位栏时失败：截图显示 A1 的新值已写入，但焦点/选区仍停留 A2。脚本改为等待 Enter 导航到 A2 及下一动画帧恢复网格焦点后，再填写定位栏，复测通过。初次失败记录保存在 firefox-initial-run.json；没有将其覆写为通过。此差异提示产品延迟恢复焦点可能与极快的外部操作竞态，仍需单独检查，不能以增加等待证明竞态不存在。

复跑：启动当前站点的 4273 端口预览后，设置 PLAYWRIGHT_MODULE 指向 Playwright index.mjs、BROWSER_ENGINE 为 chromium/firefox/webkit，串行运行 `node scripts/browser-performance.mjs`。脚本从界面启动任务、实际下载报告、检查完成状态和公式值，不使用受控 Worker 替身。summary.json 保留环境、汇总和最终脚本哈希；Chrome 执行于添加 Firefox 焦点等待之前，操作与测量顺序一致。

尚待正式候选的干净构建、重复测量、明确性能预算、峰值及 Worker 总内存、真实业务语料、正式 Safari 和物理触控/原生 IME。此目录不提供 stable-release.json。

# JavaScript 公式支持与兼容边界

公式由词法分析器和语法树解释执行，不使用 `eval` 或 `Function`。支持 A1 引用、绝对/相对引用、跨工作表引用、范围、算术运算、比较和字符串拼接；未知函数返回 `#NAME?`。这是一组明确支持的函数，不代表完整 Excel 或 SpreadJS 函数兼容。

## 支持的函数

| 分类     | 函数                                                    |
| -------- | ------------------------------------------------------- |
| 汇总     | SUM、AVERAGE、MIN、MAX、COUNT、COUNTA                   |
| 条件汇总 | SUMIF、COUNTIF、SUMIFS、COUNTIFS、SUMPRODUCT            |
| 逻辑     | IF、IFERROR、AND、OR、NOT                               |
| 查找引用 | VLOOKUP、INDEX、MATCH、XLOOKUP                          |
| 数值     | ROUND、ROUNDUP、ROUNDDOWN、MOD、INT、ABS                |
| 文本     | LEN、UPPER、LOWER、CONCAT、CONCATENATE                  |
| 日期     | TODAY、DATE、DATEVALUE、YEAR、MONTH、DAY、DAYS、EOMONTH |

## 本次扩展的语义

- `IF` 和 `IFERROR` 只计算被选中的分支。`AND`、`OR` 会计算所有参数，因此后续参数中的错误仍会传播；范围和单元格引用内的文本、空白被忽略。直接传入的字符串仅接受大小写不敏感的 `TRUE`、`FALSE`，其他文本返回 `#VALUE!`。没有可用逻辑值时返回 `#VALUE!`。
- `SUMIFS`、`COUNTIFS` 要求各范围的行数、列数均一致，同长度的横向与纵向范围不能混用；尺寸不一致返回 `#VALUE!`。条件支持比较运算符、`*`、`?` 及 `~` 转义。
- `INDEX` 当前返回单个单元格。对单行范围使用两个参数时，第二参数作为列位置；不支持行/列参数为零时返回整列/整行的数组形式。
- `MATCH` 仅接受一维范围。精确模式 `0` 支持大小写不敏感的文本和 `*`、`?`、`~` 通配符；模式 `1` 要求升序输入，模式 `-1` 要求降序输入。二维输入返回 `#VALUE!`。
- `XLOOKUP` 的查找范围和返回范围必须都是一维，并且具有相同方向和尺寸。匹配模式支持 `0`（精确）、`-1`（精确或最近较小值）、`1`（精确或最近较大值），可用于未排序范围。搜索方向支持 `1`（从前向后）和 `-1`（从后向前），同值候选按搜索方向选择。缺省值表达式仅在未找到候选时计算。
- `XLOOKUP` 暂不支持通配符匹配模式 `2`、二分搜索模式 `2` / `-2`、多列/多行返回数组；这些模式或范围返回 `#VALUE!`，不会静默忽略参数。
- `SUMPRODUCT` 接受 1–255 个参数。参数可以全部是标量，或全部是二维数组；数组参数必须具有完全相同的行数和列数，横向与纵向数组不能混用，参数中的标量不会广播到数组。直接成员只有数字参与计算，文本（包含数字文本）、布尔值和空白都按 `0` 处理。仅 `SUMPRODUCT` 的参数表达式启用逐元素比较和算术：同形数组可运算，表达式中的标量可广播，例如 `SUMPRODUCT((A2:A100="完成")*B2:B100)` 或 `SUMPRODUCT(--(A2:A100="完成"),B2:B100)`；显式算术会把空白转为 `0`、布尔值转为 `1/0`、数字文本转为数字，其他文本返回 `#VALUE!`。除零和引用错误原样传播，乘积或总和溢出返回 `#NUM!`。每个范围仍受最多 100,000 个单元格的限制；普通公式的范围运算仍保留原有单值语义，没有动态数组溢出。
- `MOD` 使用 Excel 的余数符号规则：结果符号与除数相同；除数为零返回 `#DIV/0!`。`INT` 向负无穷取整（例如 `INT(-3.1)` 为 `-4`）。这两个函数接受数值、布尔值和数字文本的常规数值转换，其他文本返回 `#VALUE!`；非有限结果返回 `#NUM!`。

## 日期

使用 Excel **1900 日期系统**：`1900-01-01` 为序列 `1`，保留 Excel 历史兼容行为中的序列 `60 = 1900-02-29`，`1900-03-01` 为 `61`。`YEAR`、`MONTH`、`DAY`、日期显示和月末计算都处理序列 `60`。不支持 1904 日期系统。

文本日期只接受严格的 **`YYYY-MM-DD`** 格式（年份 `1900–9999`）。不接受地区相关日期格式、日期时间、时区后缀或自动纠正的无效日期，例如 `02/03/2024`、`2024-04-31` 均返回 `#VALUE!`。解析不依赖宿主时区；`TODAY` 使用宿主当前本地日期。数值日期接受非负 Excel 序列，范围上限为 `9999-12-31`；负数和超界值返回 `#NUM!`。

`DATE` 按数值的年、月、日构造日期，支持月份和天数溢出归一化；`0–1899` 的年参数加上 `1900`。`DATEVALUE`、`YEAR`、`MONTH`、`DAY`、`DAYS`、`EOMONTH` 的文本输入遵循上述严格 ISO 格式，不声称完整的 Excel 本地化日期解析兼容。

## 执行限制

单个公式最长 8,192 个字符，语法嵌套深度上限 128，引用递归设有上限；单个范围最多读取 100,000 个单元格。公式循环返回 `#CYCLE!`，超限范围返回 `#NUM!`。当前没有动态数组溢出、命名范围、结构化表引用、宏、外部工作簿引用或完整的区域设置兼容。

回归测试位于 `tests/engine.test.ts` 和 `tests/engine-extended.test.ts`，包含错误传播、形状不匹配、查找方向、最近值、惰性分支、通配符和 1900 日期边界。

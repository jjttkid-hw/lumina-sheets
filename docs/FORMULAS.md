# JavaScript 公式支持与兼容边界

公式由词法分析器和语法树解释执行，不使用 `eval` 或 `Function`。支持 A1 引用、绝对/相对引用、跨工作表引用、范围、算术运算、比较和字符串拼接；未知函数返回 `#NAME?`。这是一组明确支持的函数，不代表完整 Excel 或 SpreadJS 函数兼容。

双引号内容是文字，即使内容是减号、括号或逗号也不会参与语法解析。单引号只用于工作表限定名，例如 `'O''Brien 数据'!A1`，不能用于单独包裹地址或布尔值；`Data!"A1"` 之类将地址写成文字的输入返回引用错误。范围两端显式限定同一工作表时，表名比较不区分大小写；跨两个不同工作表的范围不受支持。

## 支持的函数

工作空间公式栏获得焦点时，会为以已知函数开头的公式显示参数签名与中文用途；覆盖下列全部 54 个名称。当前只提示最外层函数，不根据光标定位嵌套参数，也不自动改写草稿。方括号表示可省略的尾部参数，不支持连续逗号省略中间参数。

| 分类     | 函数                                                    |
| -------- | ------------------------------------------------------- |
| 汇总     | SUM、AVERAGE、MIN、MAX、COUNT、COUNTA                   |
| 条件汇总 | SUMIF、COUNTIF、SUMIFS、COUNTIFS、SUMPRODUCT            |
| 逻辑     | IF、IFERROR、AND、OR、NOT                               |
| 查找引用 | VLOOKUP、INDEX、MATCH、XLOOKUP                          |
| 数值     | ROUND、ROUNDUP、ROUNDDOWN、MOD、INT、ABS                |
| 文本     | LEN、UPPER、LOWER、CONCAT、CONCATENATE、LEFT、RIGHT、MID、TRIM、CLEAN、FIND、REPLACE、SUBSTITUTE                  |
| 日期     | TODAY、DATE、DATEVALUE、YEAR、MONTH、DAY、DAYS、EOMONTH |
| 财务     | PMT、PV、FV、NPV、NPER、IRR、RATE |

## 文本提取与清理

`LEFT(text,[num_chars])` 和 `RIGHT(text,[num_chars])` 默认取一个字符；`MID(text,start_num,num_chars)` 从 1 起计位置。长度允许零、小数向零取整，负长度或小于 1 的起点返回 #VALUE!；起点超过文本长度返回空字符串，超大长度只截取已有内容。数字和布尔值沿用文本转换规则，公式错误传播。

`FIND(find_text,within_text,[start_num])` 区分大小写、按文字原样查找（没有通配符），返回从 1 开始的位置；未找到、起点小于 1 或超过原文长度返回 #VALUE!。空查找文字返回有效起点。`REPLACE(old_text,start_num,num_chars,new_text)` 按位置替换，零长度表示插入，起点超出末尾时追加。`SUBSTITUTE(text,old_text,new_text,[instance_num])` 按文字原样替换全部不重叠匹配，或仅替换指定次序；区分大小写，空 old_text 不改变原文，指定次数小于 1 返回 #VALUE!。位置、长度和次数的小数向零取整；负长度拒绝。替换结果同样受 32,767 字符上限约束。

当前 FIND/REPLACE 及 LEFT/RIGHT/MID 与 LEN 一致，按 UTF-16 代码单元计数；中文基本字符占 1，emoji 等补充字符通常占 2，截断位置可能拆开代理对。尚未实现新版 Excel 兼容模式的 Unicode 码点计数，也不是可见字素计数。

`TRIM(text)` 仅清除首尾 ASCII 空格并将连续 ASCII 空格压为一个；不会清除不换行空格、全角空格或制表符。`CLEAN(text)` 删除 U+0000–U+001F 控制字符，保留其他 Unicode 字符与 U+007F。可组合 `TRIM(CLEAN(A1))` 处理导入数据，但不把所有 Unicode 空白视为无意义内容。

## 定期现金流

`PMT(rate,nper,pv,[fv],[type])` 计算等额每期付款，`PV(rate,nper,pmt,[fv],[type])` 计算现值，`FV(rate,nper,pmt,[pv],[type])` 计算终值。方括号参数可省略尾部，默认 0；尚不支持用连续逗号省略中间参数。收款与付款使用相反符号。利率必须与期数使用相同周期，例如年利率 8% 的月供使用 `0.08/12`。

当前支持每期利率大于 -1、非负期数（允许小数）、`type` 严格为 0（期末）或 1（期初）。范围之外返回 `#NUM!`；PMT 的零期数返回 `#DIV/0!`，PV/FV 零期数返回相反符号的终值/现值。参数沿用数值转换规则，非法文本返回 `#VALUE!`，公式错误传播。零利率使用线性公式，接近零的利率使用 log1p/expm1 降低消减误差；中间值或结果溢出返回 `#NUM!`。这是明确的支持域，不宣称所有 Excel 财务边界均兼容。

示例：`PMT(0.08/12,120,10000)` 约为 -121.327594，`FV(0.06/12,120,-200,-1000)` 约为 34595.266095。未包含税费、非规则付款日期或商业贷款合同中的舍入规则。

`NPV(rate,value1,[value2],...)` 按等间隔期末现金流计算净现值，第一笔按第 1 期折现。当期初始投资在函数外加上，例如 `NPV(0.1,3000,4200,6800)-10000` 约为 1307.287754。现金流按参数顺序、每个矩形范围按行优先顺序排列。引用/范围中的文本（含数字文本）、布尔与空白忽略且不占期数；数值零占一期。直接数字文本和布尔参数按数值转换，非法文本报错；范围内公式错误仍传播。需要保留空白年份时请填数值零。

NPV 接受 2–255 个总参数（含利率），累计最多访问 100,000 个现金流成员，忽略的成员也计入工作量上限；每个范围仍受引擎范围限制。支持 rate > -1；rate = -1 返回 #DIV/0!，更低利率及中间值/结果溢出返回 #NUM!。补偿求和降低大小现金流抵消误差，但采用 IEEE 754 浮点数，不是任意精度货币核算。尚不支持日期不规则现金流的 XNPV，也未经过各 Excel/WPS 版本认证。

`NPER(rate,pmt,pv,[fv],[type])` 计算等额付款所需期数，尾部 fv/type 默认 0。支持 rate > -1，type 为 0/1；结果允许非负小数，例如 `NPER(0,-100,1250)` 为 12.5。付款和本金/目标金额遵循现金流符号约定。零利率使用线性解，非零利率使用对数解，并缩放金额以减少中间溢出、使用 log1p 保留极小利率精度。不可能达到的目标、负期数或非有限结果返回 #NUM!；零利率且零付款、以及余额恒定导致期数不唯一的情形返回 #DIV/0!。全部金额为零也属于不唯一期数。仍使用 IEEE 754，极端量级比例下可能下溢；不宣称与 Excel 所有边界完全一致，也不包含贷款合同的逐期舍入规则。

`IRR(values,[guess])` 计算等间隔现金流的内部收益率，首个值为第 0 期，参数可以是一个一维范围或多个现金流参数；`guess` 默认 `0.1`。`RATE(nper,pmt,pv,[fv],[type],[guess])` 计算等额现金流的周期利率，`type` 只能是 0（期末）或 1（期初），`guess` 默认 `0.1`。两者都使用受边界保护的牛顿迭代并在失败时进行区间二分，搜索范围为大于 -1 且不超过 1,000,000 的利率；没有正负现金流、期数非正、无根或结果非有限时返回 `#NUM!`。范围中的文字和空白不会伪造现金流，公式错误仍会传播。结果使用 IEEE 754 浮点数，不承诺多重根场景与 Excel 选择相同的根，也不支持 XIRR 的不规则日期现金流。

## 本次扩展的语义

- `IF` 和 `IFERROR` 只计算被选中的分支。`AND`、`OR` 会计算所有参数，因此后续参数中的错误仍会传播；范围和单元格引用内的文本、空白被忽略。直接传入的字符串仅接受大小写不敏感的 `TRUE`、`FALSE`，其他文本返回 `#VALUE!`。没有可用逻辑值时返回 `#VALUE!`。
- `SUMIFS`、`COUNTIFS` 要求各范围的行数、列数均一致，同长度的横向与纵向范围不能混用；尺寸不一致返回 `#VALUE!`。条件支持比较运算符、`*`、`?` 及 `~` 转义。
- `INDEX` 当前返回单个单元格。对单行范围使用两个参数时，第二参数作为列位置；不支持行/列参数为零时返回整列/整行的数组形式。
- `MATCH` 仅接受一维范围。精确模式 `0` 支持大小写不敏感的文本和 `*`、`?`、`~` 通配符；模式 `1` 要求升序输入，模式 `-1` 要求降序输入。二维输入返回 `#VALUE!`。
- `XLOOKUP` 的查找范围和返回范围必须都是一维，并且具有相同方向和尺寸。匹配模式支持 `0`（精确）、`-1`（精确或最近较小值）、`1`（精确或最近较大值），可用于未排序范围。搜索方向支持 `1`（从前向后）和 `-1`（从后向前），同值候选按搜索方向选择。缺省值表达式仅在未找到候选时计算。
- `VLOOKUP` 精确模式 FALSE 对含 `*`、`?`、`~` 的文字使用通配匹配，返回首个匹配行；近似模式继续按排序比较语义处理，不启用通配符。
- `XLOOKUP` 匹配模式 `2` 支持大小写不敏感的 `*`、`?` 与 `~` 转义，可按搜索方向 `1` / `-1` 取首个/末个匹配；数字查找仍按数值匹配，不将数字候选转换成通配文字。模式 `0` 保持原样比较。未找到时才计算备用值，预算超限返回 #NUM!，不会冒充“未找到”。
- `XLOOKUP` 暂不支持二分搜索模式 `2` / `-2`、多列/多行返回数组；这些模式或范围返回 `#VALUE!`，不会静默忽略参数。
- `SUMPRODUCT` 接受 1–255 个参数。参数可以全部是标量，或全部是二维数组；数组参数必须具有完全相同的行数和列数，横向与纵向数组不能混用，参数中的标量不会广播到数组。直接成员只有数字参与计算，文本（包含数字文本）、布尔值和空白都按 `0` 处理。仅 `SUMPRODUCT` 的参数表达式启用逐元素比较和算术：同形数组可运算，表达式中的标量可广播，例如 `SUMPRODUCT((A2:A100="完成")*B2:B100)` 或 `SUMPRODUCT(--(A2:A100="完成"),B2:B100)`；显式算术会把空白转为 `0`、布尔值转为 `1/0`、数字文本转为数字，其他文本返回 `#VALUE!`。除零和引用错误原样传播，乘积或总和溢出返回 `#NUM!`。每个范围仍受最多 100,000 个单元格的限制；普通公式的范围运算仍保留原有单值语义，没有动态数组溢出。
- `MOD` 使用 Excel 的余数符号规则：结果符号与除数相同；除数为零返回 `#DIV/0!`。`INT` 向负无穷取整（例如 `INT(-3.1)` 为 `-4`）。这两个函数接受数值、布尔值和数字文本的常规数值转换，其他文本返回 `#VALUE!`；非有限结果返回 `#NUM!`。

## 查找读取边界

INDEX、VLOOKUP、XLOOKUP 对直接 A1 范围先读取形状、再按查找过程读取实际需要的单元格；无关返回格中的公式错误不会提前中断成功查找。选中的错误格仍传播错误，搜索途中读取到的错误也传播；精确查找成功后不继续读取后面的候选。范围表达式（而非直接 A1 范围）仍先求值。依赖索引注册完整范围，因此范围内编辑仍可触发重算；这不是仅记录命中格的依赖优化。空格结果沿用当前引擎的空字符串语义，尚不等同于 Excel 部分查找场景的数值零显示。

## 日期

使用 Excel **1900 日期系统**：`1900-01-01` 为序列 `1`，保留 Excel 历史兼容行为中的序列 `60 = 1900-02-29`，`1900-03-01` 为 `61`。`YEAR`、`MONTH`、`DAY`、日期显示和月末计算都处理序列 `60`。不支持 1904 日期系统。

XLSX 导入在 ExcelJS 日期转换前保留原始数值序列，避免 JavaScript Date 无法表达 1900-02-29、早期日期偏移及毫秒舍入导致的小数精度损失。文件声明 1904 日期系统时会明确拒绝，需先在原文件中转换为 1900 系统；不会只修改标记后套用原始数值。日期格式仍转换为产品支持的格式子集，不保证自定义日期时间显示样式逐字往返。

文本日期只接受严格的 **`YYYY-MM-DD`** 格式（年份 `1900–9999`）。不接受地区相关日期格式、日期时间、时区后缀或自动纠正的无效日期，例如 `02/03/2024`、`2024-04-31` 均返回 `#VALUE!`。解析不依赖宿主时区；`TODAY` 使用宿主当前本地日期。数值日期接受非负 Excel 序列，范围上限为 `9999-12-31`；负数和超界值返回 `#NUM!`。

`DATE` 按数值的年、月、日构造日期，支持月份和天数溢出归一化；`0–1899` 的年参数加上 `1900`。`DATEVALUE`、`YEAR`、`MONTH`、`DAY`、`DAYS`、`EOMONTH` 的文本输入遵循上述严格 ISO 格式，不声称完整的 Excel 本地化日期解析兼容。

## 执行限制

COUNTIF/SUMIF、COUNTIFS/SUMIFS 的通配条件、MATCH 精确文字查找、VLOOKUP 精确通配文字及 XLOOKUP 模式 2 使用显式通配匹配，不生成带多段 `.*` 的回溯正则。`*`、`?` 可匹配换行，`~` 转义下一个字符；匹配整个值，不忽略末尾换行。每个已编译条件在一次范围扫描中共享最多 20,000,000 步匹配预算，超限返回 #NUM!（可由 IFERROR 捕获）。这限制匹配工作量，不是浏览器毫秒性能保证，也不是整个公式的统一时间预算。保留既有字符单位：MATCH/VLOOKUP/XLOOKUP 的 `?` 按 Unicode 码点，条件统计按 UTF-16 单元；尚未统一为 Excel 兼容模式。

公式文本结果最多 32,767 个 UTF-16 代码单元，超限返回 #VALUE!，可用 IFERROR 处理。`&` 和 CONCAT/CONCATENATE 在拼接前检查长度，避免引用链指数增长；大小写转换后也检查扩展长度。CONCAT/CONCATENATE 接受 1–255 个参数，按参数顺序及范围行优先顺序拼接，一次只处理一个参数范围。该限制针对计算结果，不会截断存储的输入值，也不替代现有文件导入配额；直接 API 输入的超长原始值仍需由调用方校验。

单个公式最长 8,192 个字符，语法嵌套深度上限 128，引用递归设有上限；单个范围最多读取 100,000 个单元格。公式循环返回 `#CYCLE!`，超限范围返回 `#NUM!`。当前没有动态数组溢出、命名范围、结构化表引用、宏、外部工作簿引用或完整的区域设置兼容。

回归测试位于 `tests/engine.test.ts` 和 `tests/engine-extended.test.ts`，包含错误传播、形状不匹配、查找方向、最近值、惰性分支、通配符和 1900 日期边界。


## XLSX 公式缓存

XLSX 导出保留公式正文，并写入本引擎的当前计算结果。字符串缓存使用 OOXML ST_Xstring 编码，避免 CR/CRLF、控制字符和 `_xHHHH_` 形状的文字丢失或变义；数值、布尔和错误使用各自类型。工作簿 fullCalcOnLoad 标记要求 Excel 打开后重新计算，是否执行取决于宿主应用设置，不代表所有公式已兼容。

本产品导入读取公式并重新计算，不依赖文件内的旧缓存。ExcelJS 4.4 对公式字符串缓存的读取缺少 ST_Xstring 解码，直接读取可能看到转义串；文件测试同时核对原 XML 的缓存编码和本产品重算结果，不把这项测试声称为真实 Excel 应用验收。公式正文自身的特殊字符/完整语法与其他 XML 属性兼容不属于本次缓存修复。


数值字面量边界：1e999 等转为非有限 Number 的公式数字在实际求值时返回 #NUM!，不会参与比较或拼接成 Infinity 文本。IFERROR(1e999,42) 返回 42，IF(FALSE,1e999,7) 返回 7；未选分支仍不求值。CSV 输出错误文本，XLSX 保留原公式并使用错误类型缓存。此修复不提供任意精度十进制或完整 Excel 数值兼容；手工输入与公式数字的转换契约不同，详见 SDK.md 的 parseCellInput。

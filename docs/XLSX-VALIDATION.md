# XLSX 数据验证转换

v0.5 支持将一部分 SDK 数据验证规则写入 XLSX，并从原始 XLSX 读取为 SDK 规则。转换保留受支持规则的范围、数值类型、比较边界、空白设置和错误文案。**它不是 Excel 与 JavaScript 验证行为完全相同的保证。** JSON 仍是保留 SDK 严格类型、规则 ID 和全部原有语义的格式。

## 支持范围

| SDK 规则     | XLSX 表达                          | 限制                                           |
| ------------ | ---------------------------------- | ---------------------------------------------- |
| `whole`      | whole + 常量数字边界               | 安全整数边界，拒绝单元格引用与公式             |
| `decimal`    | decimal + 常量数字边界             | 有限数字边界，拒绝引用与公式                   |
| `textLength` | textLength + 常量长度边界          | XLSX 客户端的 Unicode 长度行为可能与 SDK 不同  |
| `list`       | 双引号包围、逗号分隔的内联文本列表 | 仅非空文本，不包含逗号、双引号、换行或控制字符 |

所有数值比较运算符均支持。列表按 OOXML 标准表示为 `"待审核,已通过,拒绝"`，XML 编码负责转义包围引号；本实现不尝试用额外引号转义列表值内部的逗号或双引号，因为那不能可靠表达为一个原始选项。包含外层引号的完整列表公式最多 255 个 UTF-16 代码单元，错误消息最多 225 个代码单元。

导出生成 `showErrorMessage=true`、`errorStyle=stop`。导入只接受启用错误提示的 Stop 规则；关闭提示、Warning/Information 模式或其他未知设置不会被默默改成强制拒绝。输入提示、提示标题、自定义错误标题、下拉控制属性尚未提供转换，存在这些不能保留的内容时明确拒绝。

SDK 可对一格应用多条约束；Excel 每格只能保留一条数据验证。因此任何重叠范围都会拒绝，包括规则内容相同的重叠。跨工作表的 `sheetId` 也不能静默丢弃。导入为每个范围生成 `xlsx-validation-N` ID；SDK 自定义 ID 不是标准 OOXML 字段，XLSX 往返不会保留该 ID。

## 行为差异

- SDK 列表比较区分类型和大小写；Excel 列表验证一般不区分大小写，数字文本还可能被 Excel 输入解析成数字。因此数字/布尔 SDK 列表直接拒绝转换；字符串列表在 Excel 编辑时仍不能获得 SDK 的严格类型保证。导入回 SDK 后继续使用严格字符串规则。
- SDK `whole` / `decimal` 不把数字文本或布尔值转为数字。Excel 单元格编辑可能先做输入转换，再验证数值；同一段键盘输入在不同客户端不一定产生相同类型。
- SDK 文本长度按 Unicode 码点统计。Excel 的 `LEN`/文本长度规则会受版本和兼容性设置影响，代理对、组合字符、变体选择符和家庭 emoji 不保证与 SDK 一致。这里保留长度规则的数字边界，不转换数据、不改写 JS 长度语义。
- `allowBlank` 保留原布尔设置，原始 OOXML 未写该属性时按 `false` 读取。SDK 只把 `''` 当空白；Excel 对空单元格、公式结果空字符串与列表中的空项另有行为，未作完全兼容承诺。
- Excel 的复制粘贴、外部程序写文件可能绕过数据验证；本模块不把规则存在等同于已有数据都通过，也不提供 Excel 桌面行为认证。

## 不支持与拒绝策略

日期、时间、自定义公式、命名范围、引用列表、外部工作簿链接、任何带表达式的数值边界、x14 扩展验证、未知属性、冲突或超限规则都清晰报错，不会悄悄移除。错误为 `XlsxValidationError`，包含 `code:'XLSX_VALIDATION_UNSUPPORTED'` 和相关地址（若有）。安全 ZIP/XML 读取失败会保留归档层错误。

## 紧凑范围与导入顺序

`exportXlsxValidationRules(ws, sheet)` 先校验全部规则，成功后通过 ExcelJS `dataValidations.add('A1:A1048576', rule)` 添加范围。不会调用每个空白单元格的 `getCell()`，不会物化百万行。目标应是没有已有验证的导出工作表。

不可信文件必须先执行 `extractXlsxValidationRules(bufferOrArchive)`。它读取原始 OOXML，返回以工作表名称为键的规则 Map，保留矩形范围并支持 `sqref` 中的多个不连续分片；之后 ExcelJS 必须使用 `{ignoreNodes:['dataValidations']}` 加载。

这个顺序是必要的：ExcelJS 默认导入会把范围展开成逐格模型，还可能把 `whole`/`decimal` 的公式源文本经 `parseInt`/`parseFloat` 转成数字。原始 XML 预检避免百万范围展开，也确保 `1+2` 不会被误接纳成常量 `1`。

`importXlsxValidationRules(ws, sheetId)` 仅供已经信任的 ExcelJS 模型适配，能合并连续的同规则单元格，不应用于替代原始文件预检。已展开的模型最多 100,000 项，结果最多 1,000 个矩形；原始 XML 也最多接收 1,000 个范围。共享 ZIP/XML 层另外限制压缩、解压、XML 深度、节点和工作表数量，见 `XLSX_ARCHIVE_LIMITS`。

`tests/xlsx-validation.test.ts` 使用真实 XLSX 写入和重新读取，覆盖百万行规则保持一条范围、实际存储单元格不增长、多片范围、列表 XML、错误提示、空白策略及拒绝不支持的原始规则。测试没有声称经过各版本 Excel/WPS 的交互认证。

底层 `extractXlsxValidationRules()` 可以读取 Excel 行列上限内的紧凑范围；完整 `workbookFromXlsx()` 还要遵守应用导入配额（最多 100,000 行、256 列、100,000 个存储单元格）。导入时会把验证范围、重复标题和手动分页的逻辑末端纳入工作表尺寸；如果这些元数据超过导入配额，文件会明确拒绝，不会截断或悄悄缩小范围。
